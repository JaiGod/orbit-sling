## 🌌 About

You are a mission navigator. Every level gives you one probe on a launch pad, a few gold **checkpoint rings** and a **target moon**. Drag back like a slingshot, release, and let planets, moons and black holes bend your path with real **inverse-square gravity**. Collect every ring to unlock the moon, then land on it.

Everything you see and hear is made in code: procedural starfields and nebulae, glowing planets, swirling accretion disks, and a synthesized ambient soundtrack. No images, no audio files, no libraries.

## ✨ Features

- 🪐 **Real gravity simulation**: inverse-square attraction from every body, a fixed 120 Hz physics step, and softened close passes.
- 🎯 **24 handcrafted missions** with rising difficulty: gravity assists, moving moons, orbiting targets, black holes, asteroid walls and belts, a spinning asteroid ring, and fuel-limited thrust nudges.
- 🔭 **Trajectory preview**: a dotted predicted path that marks ring hits, crashes and landings. It gets shorter on harder levels.
- ⭐ **Star ratings**: 3 stars for a one-launch solve, 2 for three launches or fewer. Progress and stars are saved locally.
- ☄️ **Daily Mission**: an endless run of seeded random sectors that are the same for everyone on the same day. Each one is generated by simulating a real flight path, so every sector is solvable. You start with 5 probes and earn one back per cleared sector.
- 🎵 **Synthesized ambient music and SFX** (Web Audio): drone pads, pentatonic plucks over an Am-F-C-G progression, a delay "space" reverb, a thruster hiss, ring chimes and crash booms.
- ✨ **Juice**: particle bursts, screen shake, flashes, a glowing probe trail, pulsing rings and rotating moon locks.
- 📱 **Touch and mouse**, responsive down to 390 px phones, with pause, mute, auto-pause when the tab is hidden, and safe-area support.

## 🎮 Controls

| Action | Mouse / Touch | Keyboard |
|---|---|---|
| Aim and launch | Drag back anywhere, then release | Arrows / WASD to aim and set power, **Space** to launch |
| Thrust (fuel levels) | Hold the screen; the probe thrusts toward your finger | Arrows / WASD during flight |
| Retry | ↻ button | **R** |
| Pause | ❚❚ button | **P** / **Esc** |
| Sound | 🔊 button | **M** |

## 🛠️ Tech Stack

- **HTML5 Canvas 2D** for all rendering, with DPR-aware scaling and an additive-blend glow pipeline
- **Vanilla JavaScript**: a custom physics engine, level system, seeded RNG (mulberry32) and procedural generator
- **Web Audio API**: all music and sound effects are synthesized at runtime
- **Capacitor 6 + GitHub Actions**: an Android APK is built automatically on every push
- **GitHub Pages**: hosting

## 📓 Development Log

**Day 1: Physics first.** I started with the core loop: a probe, a list of bodies, and `a = GM·d / (|d|² + ε²)^1.5`. A tiny softening term (ε² = 100) stops the probe from getting infinite acceleration when it skims a black hole. I chose semi-implicit (symplectic) Euler at a fixed 1/120 s step because it keeps orbits stable without drifting outward the way plain Euler does.

**Moving moons were a design problem.** At first the moons orbited all the time, even while you were aiming, so the preview depended on *when* you let go. That felt unfair. Now the whole system is frozen at its launch configuration while you aim (faint orbit lines and a "next position" dot show where things will go), and the clock starts at launch. The game stays deterministic, the preview stays honest, and the timing puzzle is still there.

**Proving levels are solvable.** Hand-placing rings around gravity wells is really hard to get right by eye. Many of my first layouts had zero solutions. So I wrote a brute-force solver that runs the real game physics in headless Chromium and sweeps 360 angles × 35 power settings (12,600 flights per level). For layouts with no solution, a tuning script searches for the flight that passes closest to my intended ring and moon spots, then snaps them onto that real path while keeping the level's shape. Every one of the 24 missions is now verified solvable, and I reordered them by measured "solution density" so the difficulty curve is smooth.

**A procedural generator that can't make impossible levels.** Daily Mission sectors are generated the same way. The generator places bodies, simulates random launches until it finds a long, in-bounds flight, and then drops the rings and moon *along that flight*. The seed is the date plus the sector number, so everyone gets the same sequence each day.

**Asteroid fields vs. tuning.** Fields are seeded, but they originally avoided ring positions while generating, so moving a ring reshuffled the whole field and broke the tuned path. The fix was to generate candidates independently of rings and then *filter* out rocks near rings. Moving a ring can now only remove rocks, never add them.

**Phones.** The playfield is a fixed 1000×1000 world scaled to fit, which made text and the probe tiny on a 390 px phone. I added a UI scale factor so labels, the probe, the preview dots and the aim arrow grow when the world is small. I also made the drag-to-power distance relative to the screen size so precision feels the same everywhere.

**Sound.** All audio is generated: four detuned oscillators through LFO-swept low-pass filters make the drone, a look-ahead scheduler plays soft sine plucks over a chord progression, and a feedback delay gives it some "space". The thruster is looping noise through a band-pass filter whose gain follows your input.
